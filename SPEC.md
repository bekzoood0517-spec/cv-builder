| | |
|---|---|
| Документ | Техническая спецификация MVP |
| Основание | `PRD.md` версии 1.0 от 17 ноября 2026 |

Спецификация фиксирует контракты, которые нельзя менять по ходу экрана. Всё, чего нет в PRD и в этом файле, в MVP не делается.

## 1. Система

Одно веб-приложение. Анкета, предпросмотр, шаблоны и PDF работают в браузере без аккаунта. Сервер нужен только для генерации текстов и не хранит профиль.

```text
Браузер
  Анкета → Project
  Project → предпросмотр (те же данные, что и PDF)
  Project → PDF A4 / PDF mobile / ZIP / JSON
        │
        └─ запрос без фото → POST /v1/generate → тексты
```

Модули клиента:

| Модуль | Ответственность |
|---|---|
| `project` | Схема, значения по умолчанию, миграция `schemaVersion` |
| `validate` | Ошибки полей, допуск к скачиванию и к генерации |
| `facts` | Индекс фактов анкеты и проверка ответа ИИ |
| `derive` | Ф. И. О., возраст, порядок записей, пересечение дат, актуальность писем |
| `store` | Автосохранение, импорт и экспорт JSON |
| `render` | Дерево документа для предпросмотра и для PDF |
| `pdf` | Сборка файлов, ссылки, шрифты, ZIP |
| `ai` | Запросы генерации и подтверждение замены правок |

Нормативный стек MVP: TypeScript, Vite, React, Zod, локальная сборка PDF библиотекой, которая пишет текстовые глифы, а не растр страницы. Шрифт PDF и интерфейса — Source Sans 3 (кириллица, начертания 400, 600, 700), файлы шрифта вшиваются в PDF подмножеством использованных символов.

## 2. Документ Project

Корень:

```ts
type Project = {
  schemaVersion: 1
  profile: Profile
  experienceSummary: string
  jobs: Job[]
  education: Education[]
  skills: Skill[]
  generated: Generated
  letters: {
    motivation: MotivationLetter
    recommendation: RecommendationLetter
  }
  design: {
    template: "classic" | "modern" | "minimal" | "accent"
    palette: "ink" | "sea" | "terracotta" | "forest" | "graphite"
  }
  preview: {
    document: "resume" | "motivation" | "recommendation"
    format: "a4" | "mobile"
  }
  updatedAt: string
}
```

`updatedAt` — ISO 8601 в UTC. Пустой проект: шаблон `classic`, палитра `ink`, документ `resume`, формат `a4`, массивы пустые, строки пустые, флаги зон роста `false`.

Идентификаторы записей — UUID. Длина текстов считается в кодовых единицах UTF-16, как `string.length` в JavaScript. Пробелы по краям обрезаются перед сохранением и перед отправкой в ИИ.

### 2.1. Профиль

```ts
type Profile = {
  photo: string | null
  lastName: string
  firstName: string
  middleName: string
  birthYear: number | null
  address: string
  title: string
  contacts: Contact[]
}

type Contact =
  | { id: string; kind: "phone"; value: string }
  | { id: string; kind: "email"; value: string }
  | { id: string; kind: "link"; label: "telegram" | "linkedin" | "website" | "other"; value: string }
```

| Поле | Лимит | Правило |
|---|---|---|
| `lastName`, `firstName`, `middleName` | 60 | Пустое отчество не выводится |
| `title` | 120 | |
| `address` | 160 | Одна строка, как ввёл пользователь |
| `birthYear` | — | Целое от `год − 80` до `год − 16` включительно. День и месяц не хранятся |
| `contacts` | 6 | Минимум один валидный контакт для скачивания |
| `photo` | — | `null` или data URL JPEG после обрезки |

Фото на входе: MIME `image/jpeg`, `image/png`, `image/webp`, размер файла до 5 МБ. Клиент кропает квадрат и пережимает в JPEG не шире 512 px, качество 0.82. В Project попадает только результат. В запрос ИИ поле `photo` не включается.

### 2.2. Опыт, работа, учёба, навыки

```ts
type Job = {
  id: string
  company: string
  role: string
  city: string
  start: YearMonth
  end: YearMonth | null
  current: boolean
  details: string
}

type Education = {
  id: string
  institution: string
  program: string
  level: "" | "secondary" | "college" | "bachelor" | "master" | "course" | "other"
  start: YearMonth | null
  end: YearMonth | null
  current: boolean
  note: string
}

type Skill = {
  id: string
  label: string
  level: "" | "basic" | "confident" | "advanced"
}

type YearMonth = { year: number; month: number }
```

| Сущность | Лимит | Обязательно, если запись есть |
|---|---|---|
| `experienceSummary` | 2000 | Нет |
| `jobs` | 10 | `company` 120, `role` 120, `start`; `end` обязателен, если `current = false` |
| `education` | 5 | `institution` 160; `program` 160; `note` 300 |
| `skills` | 20 | `label` 1–40 после обрезки |
| `city` | 80 | Нет |
| `details` | 1500 | Нет |

`month` — целое 1–12. `year` для работы и учёбы — от `текущий год − 70` до `текущий год + 1`. Нельзя сохранить запись, у которой окончание раньше начала. `current: true` обнуляет `end`.

Подписи уровней образования в документе: «Среднее образование», «Колледж», «Бакалавриат», «Магистратура», «Курс», «Другое». Пустой `level` не печатается.

Уровни навыков в документе: «базовый», «уверенный», «продвинутый». Пустой уровень не печатается и шкалу не рисует.

Навык сравнивается для дубля по `label.trim().toLocaleLowerCase("ru")`. Повтор сливается с уже существующей записью. Если у одной копии уровень пуст, остаётся непустой. Если оба заданы, остаётся более высокий: `advanced` > `confident` > `basic`.

### 2.3. Сгенерированные тексты

```ts
type Generated = {
  summary: string
  summarySource: "empty" | "ai" | "user"
  summaryDirty: boolean
  strengths: Strength[]
  strengthsDirty: boolean
  growth: GrowthItem[]
  growthStatus: "empty" | "ready" | "insufficient"
  growthDirty: boolean
  showGrowthInResume: boolean
  mentionGrowthInMotivation: boolean
  jobBullets: Record<string, string[] | null>
}

type Strength = { id: string; title: string; detail: string; factIds: string[] }
type GrowthItem = { id: string; limitation: string; advice: string }
```

`showGrowthInResume` и `mentionGrowthInMotivation` по умолчанию `false`.

`jobBullets[id] = null` или отсутствие ключа означает печать `jobs[].details` как абзаца. Массив из 3–5 строк — маркеры вместо абзаца. Кнопка «Вернуть мой текст» ставит `null`.

### 2.4. Письма

```ts
type MotivationLetter = {
  company: string
  vacancy: string
  reason: string
  text: string
  source: "empty" | "ai" | "user"
  dirty: boolean
  stale: boolean
  factsHash: string
}

type RecommendationLetter = {
  authorName: string
  authorRole: string
  relation: "" | "manager" | "colleague" | "teacher" | "client"
  period: string
  authorPhone: string
  authorEmail: string
  text: string
  source: "empty" | "ai" | "user"
  dirty: boolean
  stale: boolean
  factsHash: string
}
```

| Поле | Лимит |
|---|---|
| `company`, `vacancy`, `authorName`, `authorRole` | 120 |
| `reason` | 500 |
| `period` | 80 |
| `text` мотивации | 4000 |
| `text` рекомендации | 3500 |

`authorPhone` и `authorEmail` в генерацию можно не передавать: они печатаются в блоке подписи, их заполняет пользователь. Для кнопки генерации рекомендации обязательны непустые `authorName`, `authorRole` и `relation`.

## 3. Валидация

Ошибка показывается под своим полем. Скачивание и генерация смотрят на разные наборы.

Скачивание любого PDF резюме разрешено, когда после обрезки непусты `lastName`, `firstName`, `title` и есть хотя бы один контакт, прошедший проверку формата. Иначе основная и вторичная кнопки неактивны, под ними текст: «Чтобы скачать, укажите фамилию, имя, должность и хотя бы один контакт.»

| Контакт | Допустим |
|---|---|
| Телефон | 10–15 цифр после удаления пробелов, скобок и дефисов; необязательный ведущий `+` |
| Email | одна `@`, локальная и доменная части непусты, в домене есть точка |
| Ссылка | `http://`, `https://`, либо значение, которое становится адресом после добавления `https://` |

Генерация резюме разрешена при том же минимуме, что и скачивание. Генерация мотивационного письма — когда резюме уже можно скачать. Генерация рекомендации — когда резюме можно скачать и заполнены имя, роль и тип связи рекомендателя. Незаполненная рекомендация не блокирует резюме.

Пересечение периодов работы — предупреждение у карточек, не ошибка. Интервалы `[start, end]` пересекаются, если каждый начинается не позже окончания другого. `current` считается окончанием в текущем месяце.

## 4. Производные значения

Полное имя: фамилия, имя, отчество через пробел, пустые части пропускаются.

Возраст: `текущийГод − birthYear`. На экран и в PDF: «1 год», «2 года», «5 лет», «21 год» — правило русского языка по последним двум цифрам, исключения 11–14. Если года нет, строка возраста не занимает место.

Инициалы, если фото нет: первая буква имени и первая буква фамилии в верхнем регистре. Это `alt` и запасной блок шапки.

Порядок мест работы и образования по умолчанию: текущие записи выше завершённых, далее по убыванию даты окончания, затем по убыванию даты начала. Перетаскивание переводит список в ручной порядок и больше не пересортировывает его, пока пользователь не нажмёт «Сортировать по дате».

Пустая секция не попадает в дерево документа. Скрытие секции в предпросмотре ставит флаг видимости и не удаляет данные анкеты. Скрыть можно фото, возраст, адрес, описание, сильные стороны, места работы, образование, навыки и зоны роста. Фамилию, имя, должность и контакты скрыть нельзя.

Порядок секций резюме фиксирован:

1. Шапка
2. Описание
3. Сильные стороны
4. Места работы
5. Образование
6. Навыки
7. Зоны роста

В шаблоне «Современный» на A4 тот же состав раскладывается по колонкам: слева контакты, навыки, образование; справа описание, сильные стороны, места работы, зоны роста. На мобильной ширине колонки складываются в общий порядок секций.

`factsHash` считается SHA-256 от канонического JSON фактов: имя, должность, контакты, адрес, возраст только как год, `experienceSummary`, jobs, education, skills, `summary`, strengths, `mentionGrowthInMotivation`. Фото в хеш не входит. После генерации письма в него пишется текущий хеш и `stale: false`. Любое последующее отличие хеша ставит `stale: true` и не меняет `text`.

## 5. Экран

Один маршрут `/`. Шире 900 px — две колонки: слева форма 440 px, справа предпросмотр. Уже или ровно 900 px — форма на всю ширину, предпросмотр по кнопке «Смотреть резюме» на весь экран с возвратом к форме.

Слева сверху вниз: личные данные, опыт, места работы, образование, навыки, панель «Собрать резюме», контекст писем на вкладках писем. Шаблон и палитра стоят над предпросмотром, чтобы смена сразу была видна на листе.

Над листом три вкладки: «Резюме», «Мотивационное», «Рекомендация». У письма со `stale: true` на вкладке метка «устарело». Рядом переключатель «ПК» / «Телефон»: он пишет `preview.format` и определяет основную кнопку скачивания. Вторая кнопка скачивает другой формат и подпись меняет вместе с переключателем: при «ПК» основная — «Скачать PDF для ПК», вторичная — «Для телефона».

Предпросмотр — тот же набор блоков, что уйдёт в PDF, в масштабе, чтобы страница целиком помещалась по ширине панели. Цвета, колонки и кегль не рисуются отдельной упрощённой вёрсткой.

Панель анализа под кнопкой «Собрать резюме»:

- Описание с действиями «Заменить», «Оставить как есть», «Сформулировать заново».
- Сильные стороны списком.
- Зоны роста и переключатель «Показать зоны роста в резюме».
- Отдельный переключатель письма: «Упомянуть развитие в мотивационном письме». Он доступен только если `growthStatus = "ready"`.
- Пометка: «Текст собран автоматически. Проверьте факты до скачивания.» Показывается, если источник описания, сильных сторон или зон роста равен `ai`.

Ручная правка описания ставит `summarySource = "user"` и `summaryDirty = true`. То же для сильных сторон, зон роста и писем.

Повторная генерация при `dirty = true` открывает подтверждение: «Заменить ваш текст новым вариантом?» Отмена оставляет текст. Пока подтверждения нет, поле не очищается. Ответ «Сформулировать заново» кладётся рядом как черновик предложения и попадает в документ только по «Заменить».

Если `growthStatus = "insufficient"`, вместо списка текст: «Чтобы назвать зоны роста, добавьте места работы или описание опыта».

На вкладке рекомендации постоянно виден текст: «Черновик. Подписывает и отправляет рекомендатель после своей правки.»

Состояния кнопок ИИ: покой, выполнение, ошибка. Во время выполнения форма редактируется. Ошибка не сбрасывает анкету. Текст ошибки и кнопка «Продолжить без генерации» оставляют ручной ввод.

Клавиатура доходит до всех полей, вкладок и кнопок. Ошибка поля связана с полем через `aria-describedby`.

## 6. Генерация

`POST /v1/generate`

Заголовок `Content-Type: application/json`. Тело — снимок Project без `photo`, без `letters.*.text`, без `design` и без `preview`. Для `kind: "resume"` контекст писем можно не слать. Для писем слать контекст только этого письма.

```ts
type GenerateRequest = {
  kind: "resume" | "motivation" | "recommendation"
  profile: Omit<Profile, "photo">
  experienceSummary: string
  jobs: Job[]
  education: Education[]
  skills: Skill[]
  generated: {
    summary: string
    strengths: Strength[]
    growth: GrowthItem[]
    mentionGrowthInMotivation: boolean
  }
  letterContext?: MotivationLetter | RecommendationLetter
}

type GenerateResponse =
  | { ok: true; kind: "resume"; summary: string; summaryShort: boolean; strengths: Strength[]; growth: GrowthItem[] | null; growthStatus: "ready" | "insufficient"; jobBullets: Record<string, string[]> }
  | { ok: true; kind: "motivation" | "recommendation"; text: string }
  | { ok: false; error: "unavailable" | "invalid" | "timeout" }
```

Таймаут клиента — 45 секунд. Сеть, 5xx и таймаут отображаются как «Сервис формулировок сейчас недоступен. Резюме можно собрать и скачать вручную.» Ответ `invalid` — «Не удалось собрать текст по этой анкете. Поправьте поля или напишите описание сами.»

Инструкция модели входит в серверную часть запроса и не редактируется пользователем.

Общие запреты:

- Не добавлять компании, должности, города, учебные заведения, даты, числа, навыки и дипломы, которых нет во входе.
- Не писать о здоровье, внешности, семье, национальности, религии и характере.
- Не оценивать возраст как недостаток.
- Не ставить диагноз и не придумывать личные качества без опоры на факт анкеты.

Описание резюме — от первого лица, один абзац. При заполненных местах работы или при `experienceSummary` длиннее 80 символов длина 400–700. Иначе `summaryShort: true` и длина 120–400, без достижений с цифрами. Роль берётся из `title`.

Сильные стороны — 3–5 элементов, если фактов достаточно, иначе столько, сколько удалось привязать, но не больше 5. `title` до 60 символов. `detail` — одно предложение и ссылка `factIds` на id работы, учёбы, навыка или на ключ `experience`. Элемент без существующего `factIds` отбрасывается на клиенте.

Зоны роста — 2–4 элемента. У каждого есть ограничение, которое видно из дат, состава опыта или пустых полей, и один совет для отклика. Если нет ни одной работы и `experienceSummary` короче 40 символов, сервер возвращает `growth: null`, `growthStatus: "insufficient"`.

`jobBullets` — только для тех работ, где `details` непустой. 3–5 коротких строк, факты не новые. Клиент принимает маркеры только если каждая строка не содержит числа или названия компании вне индекса фактов этой работы; иначе для этой работы остаётся исходный текст.

Мотивационное письмо — 180–260 слов, слова делятся по пробелам. Структура из четырёх абзацев: приветствие «Здравствуйте»; роль (`vacancy` или иначе `title`) и один-два факта из работ, если работы есть; что человек хочет делать; закрытие с контактами из профиля. Это не список обязанностей. Зоны роста попадают в третий абзац одной фразой про развитие только при `mentionGrowthInMotivation = true` и непустом `growth`. Компания из контекста называется, только если поле `company` непустое.

Рекомендательное письмо — 150–230 слов от первого лица рекомендателя. Есть связь из `relation`, два наблюдения по фактам резюме и роль, на которую рекомендует (`title`). Подпись в текст модели не входит: её добавляет вёрстка.

Допуски длины, если модель промахнулась: описание ±15% от диапазона, письмо ±20 слов. Вне допуска клиент делает один повторный запрос. Второй неудачный ответ показывается с пометкой «Проверьте длину» и не блокирует редактирование. Пользователь может сохранить текст любой длины в пределах лимита поля.

## 7. Индекс фактов

Перед показом ответа клиент строит индекс:

- названия компаний, должностей, городов, учебных заведений, программ, навыки — отдельные фразы;
- все годы из `birthYear`, начала и окончания;
- все целые числа, которые уже есть в `experienceSummary`, `details`, `note` и `reason`.

Проверка описания, сильных сторон, маркеров и писем:

- четырёхзначное число 19xx или 20xx, которого нет в индексе лет, отклоняет весь ответ этого `kind`;
- иное целое число длиной от 2 знаков, которого нет в индексе чисел, отклоняет абзац или пункт, где оно стоит;
- если в тексте найдена последовательность, совпадающая с типичным собственным именем организации вне списка компаний и учебных заведений, пункт отклоняется.

Совпадение фраз — по нижнему регистру с ё → е. Отклонённый пункт силы или зоны роста просто не показывается. Если у описания или письма не проходит проверка года, срабатывает тот же текст, что у ошибки `invalid`, старый текст пользователя остаётся.

Пустая фикстура без работ не обязана содержать годы в описании. Фикстура с одной и с тремя работами обязана использовать только компании из анкеты.

| `terracotta` | `#3F2E2A` | `#C46B4A` | `#FBF7F4` | `#2B211E` |

Роли цвета:

Текст тела всегда цветом `text`, не акцентным. Фото не тонируется. Контраст `text` к `background` у всех пяти пар выше 4.5:1; произвольный цвет пользователю не даётся.

Письма не используют колонки резюме и не печатают фото. Это одна колонка: заголовок документа, кому или от кого, абзацы, блок контактов. Цвета те же.

Кегль A4: тело 11 pt, межстрочный интервал 1.35, имя 22 pt в «Классике» и «Минимале», 20 pt в «Современном», 26 pt в «Акценте». Заголовок секции 12 pt, полужирный, цвет акцента. Поля: «Классика» 16 мм, «Современный» 14 мм, «Минимал» 18 мм, «Акцент» 16 мм плюс полоса внутри левого поля.

Кегль мобильной версии у всех шаблонов: тело 12.5 pt, интервал 1.4, имя 24 pt, секция 14 pt. Поля 8 мм. Фото по ширине из таблицы, не больше 26 мм.

Заголовок секции не остаётся последним элементом страницы: он переносится вместе с первой строкой секции. Колонтитул со второй страницы A4: полное имя слева, номер страницы справа, 9 pt, цвет акцента. На мобильной странице колонтитул не печатается.

Страница A4 — 210 × 297 мм. Мобильная страница — 100 × 180 мм. Содержимое, не вошедшее в 180 мм, продолжается на следующей странице той же ширины.

## 9. PDF и пакет

Сборка на клиенте. Текст выделяется и копируется. Email получает ссылку `mailto:`, телефон — `tel:` из цифр и ведущего `+`, ссылка — абсолютный `https`.

Ориентир размера резюме с фото — не больше 2 МБ. Фото в PDF — тот же JPEG, что в Project.

Имена файлов собираются из фамилии и имени: обрезка, пробелы в `_`, удаление символов `\ / : * ? " < > |`. Если фамилия пуста — префикс `resume`.

| Документ | Формат | Имя |
|---|---|---|
| Резюме | A4 | `{Фамилия}_{Имя}_резюме_A4.pdf` |
| Резюме | mobile | `{Фамилия}_{Имя}_резюме_mobile.pdf` |
| Мотивационное | A4 | `{Фамилия}_{Имя}_мотивационное_A4.pdf` |
| Мотивационное | mobile | `{Фамилия}_{Имя}_мотивационное_mobile.pdf` |
| Рекомендация | A4 | `{Фамилия}_{Имя}_рекомендация_A4.pdf` |
| Рекомендация | mobile | `{Фамилия}_{Имя}_рекомендация_mobile.pdf` |

Письмо скачивается только если `text` непустой. Внизу PDF рекомендации тем же кеглем тела:

```text
Черновик. Подписывает и отправляет рекомендатель после своей правки.

{authorName}
{authorRole}
Телефон: {authorPhone или пустая линия}
Email: {authorEmail или пустая линия}
```

«Скачать пакет» собирает ZIP из отмеченных файлов. По умолчанию отмечены оба формата резюме и те письма, у которых текст непустой. Имя архива: `{Фамилия}_{Имя}_документы.zip`.

## 10. Хранение

Ключ `localStorage`: `cv-builder.project.v1`. Запись через 400 мс после изменения. При загрузке битый JSON заменяется пустым проектом, предыдущее значение остаётся в ключе `cv-builder.project.v1.bak`.

«Скачать проект» отдаёт текущий Project как `application/json`, имя `{Фамилия}_{Имя}_проект.json`. «Открыть проект» принимает файл, проверяет Zod-схемой `schemaVersion = 1` и заменяет состояние только при успехе. Ошибка импорта: «Файл проекта не подошёл. Нужен JSON конструктора резюме версии 1.» Фото приезжает внутри JSON как data URL.

Чужие поля при импорте отбрасываются. Неизвестное значение `template` или `palette` заменяется на `classic` и `ink`.

## 11. Сценарии проверки

Каждый пункт закрывает критерий приёмки PRD.

| # | Проверка | Ожидание |
|---|---|---|
| 1 | Заполнить все поля, 2 работы, 2 учёбы, перезагрузить страницу | Тот же Project в форме |
| 2 | Пустые фамилия, имя, должность или ни одного валидного контакта | Обе кнопки PDF неактивны, подпись причины на месте |
| 3 | Три фикстуры: без работ и без опыта; одна работа; три работы | В описании и сильных сторонах нет чужих компаний, лет и чисел. Мало фактов — короткое описание |
| 4 | Зоны роста готовы, переключатель выключен | Видны в панели анализа, отсутствуют в дереве PDF A4 и mobile |
| 5 | 4 шаблона × 5 палитр | Предпросмотр и PDF совпадают по колонкам и ролям цвета |
| 6 | Сменить `vacancy` и заполнить `company` | Новый текст письма, другое название роли и компании; при непустых работах есть хотя бы одна компания из анкеты |
| 7 | Пустое имя рекомендателя | Кнопка генерации неактивна. После генерации пометка черновика есть на экране и в PDF |
| 8 | Скачать 6 файлов на фикстуре из двух работ | A4 равен 210 мм; mobile равен 100 мм; mobile в одну колонку; тело mobile не меньше 12 pt |
| 9 | Открыть PDF | Фамилия копируется как текст; `mailto` и `tel` кликабельны; в файле есть глифы `ё` и `й` |
| 10 | Ответ ИИ `unavailable` | Поле описания редактируется, PDF A4 скачивается с ручным текстом |

Фикстура «одна работа» для регрессии фактов: должность «Аналитик данных», компания «Север», город «Ташкент», период 2022-03 — по настоящее время, навык «SQL», год рождения не задан. В ответе ИИ недопустимы другие компании и годы, кроме 2022 и текущего.

## 12. Поставка по модулям

| Шаг | Готово, когда |
|---|---|
| 1 | Схема, форма, `localStorage`, предпросмотр `classic` + `ink`, PDF A4 резюме без ИИ |
| 2 | Остальные шаблоны, палитры, мобильное дерево и второй PDF |
| 3 | `POST /v1/generate` для `resume`, индекс фактов, панель анализа, флаг зон роста |
| 4 | Оба письма, их актуальность по `factsHash`, четыре PDF писем |
